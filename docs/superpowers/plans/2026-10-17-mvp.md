# Looksmax Simulator MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Playable MVP: lobby map, gum + mewing tools, click-to-train with face camera, rating/Glow, 8 PSL tiers with cap, rebirth, one trainer pair, rank label under name, start menu, RU/EN, saved progress.

**Architecture:** Rojo project synced into Roblox Studio from files. Pure game math lives in `src/shared/` (no Roblox APIs) and is unit-tested with Lune outside Studio. Server owns all state (DataStore + player attributes); client only sends intents (click, buy, equip, rebirth) through RemoteEvents and renders UI from player attributes. Map is generated by a server script so no binary place file is needed.

**Tech Stack:** Luau, Rojo 7, Lune (tests), Rokit (tool manager), Roblox Studio.

**Spec:** `docs/superpowers/specs/2026-10-17-looksmax-simulator-design.md`

## Global Constraints

- Languages RU + EN; every UI string goes through `LocalizationTable` keys — no hardcoded UI text.
- Server is source of truth: rating, Glow, items, rebirths are computed only on server.
- No blood, no realistic injury visuals.
- Tier order exactly: `Sub-3, Sub-5, LTN, MTN, HTN, Chadlite, Chad, True Adam`.
- Rank label goes **under** the player name.
- Rebirth resets rating, Glow and bought items (back to gum only); keeps rebirth count and gamepasses.
- Rating never spent; Glow is shop currency. Click gives both.
- UI sizes in Scale (not Offset) so it fits phones.
- Free infrastructure only.

## Numbers (builder's call, tune later)

| Thing | Value |
|---|---|
| Tier min rating | Sub-3 0, Sub-5 1000, LTN 4000, MTN 12000, HTN 35000, Chadlite 100000, Chad 300000, True Adam 900000 |
| Top rating (True Adam cap) | 2500000 |
| Cap with `r` rebirths | `Tiers[r+2].min`, or Top rating when `r+2 > 8` |
| Max rebirths (MVP) | 7 |
| Items | `gum` power 1 price 0; `mewing` power 3 price 150 |
| Rebirth mult | `1 + 0.5 * r` |
| Passed-tier speedup | x3 when current tier index `<= r` |
| Trainer / VIP / X2 pass | x3 / x6 / x2 |
| Glow gain | equals rating gain before cap clamp |
| Server click limit | 12 accepted clicks per second per player |

## Review Focus

1. DataStore read fails on join — player must play with defaults and the session must **not** save over real progress.
2. Autoclicker / exploit firing Click remote 100x/sec — server accepts at most 12/sec.
3. Rating at cap — clicks still give Glow, rating stays clamped, rebirth button appears.
4. Player dies or unequips while camera zoomed — camera returns to normal.
5. Tampered remote args (unknown itemId, non-string, buying owned item, rebirth below cap) — ignored, no error spam.

### Task 2: Config and Progression (pure logic)

**Files:**
- Create: `src/shared/Config.luau`, `src/shared/Progression.luau`
- Test: `tests/Progression.spec.luau`

**Interfaces:**
- Produces `Config`: `Tiers: {{id: string, name: string, min: number}}`, `TopRating`, `MaxRebirths`, `Items: {[string]: {power: number, price: number, order: number}}`, `Mult = {Trainer=3, Vip=6, X2=2, PassedTier=3, PerRebirth=0.5}`, `ClickLimitPerSec = 12`, `GamePasses = {Vip = 0, X2 = 0}` (0 = not set up yet).
- Produces `Progression`:
  - `type Data = {version: number, rating: number, glow: number, rebirths: number, items: {[string]: boolean}, equipped: string}`
  - `defaultData(): Data` — `{version=1, rating=0, glow=0, rebirths=0, items={gum=true}, equipped="gum"}`
  - `tierIndex(rating: number): number` (1..8)
  - `capRating(rebirths: number): number`
  - `tierProgress(rating: number): (number, number)` — tier index, fraction 0..1 to next tier min (or to TopRating)
  - `clickGain(data: Data, ctx: {trainerMult: number, hasX2: boolean}): number`
  - `applyClick(data: Data, ctx): (number, number)` — mutates, returns rating added (after clamp), glow added
  - `canRebirth(data): boolean`, `applyRebirth(data)`
  - `canBuy(data, itemId: any): (boolean, string?)` reasons `"unknown"|"owned"|"glow"`, `applyBuy(data, itemId)`
- Requires: `local Config = if script then require(script.Parent.Config) else require("./Config")` so it runs in both Roblox and Lune.

### Task 3: Server — player data, remotes, game rules

**Files:**
- Create: `src/server/PlayerData.luau`, `src/server/Remotes.luau`, `src/server/GameService.server.luau`, `src/server/Tools.luau`

**Interfaces:**
- Consumes: `Progression`, `Config` (Task 2).
- Produces RemoteEvents in `ReplicatedStorage.Remotes`: `Click()`, `Buy(itemId)`, `Equip(itemId)`, `Rebirth()`.
- Produces player attributes (client reads these): `Rating`, `Glow`, `Rebirths`, `Equipped`, `Tier` (index), `Items` (comma-joined owned ids), `DataLoaded` (bool).
- Produces `PlayerData.get(player): Progression.Data?` and `PlayerData.publish(player)` (writes attributes).
- `Tools.give(player, data)` puts one `Tool` per owned item in Backpack (named by item id, a small part as Handle, `RequiresHandle = true`), removes unowned.
- `GameService` reads `workspace.Trainers` zones (Task 4) through `getTrainerMult(player, data): number`.

- [ ] **Step 1:** `PlayerData`: DataStore `PlayerData_v1`, key `"u_" .. userId`. Load with 3 retries (1s, 2s, 4s backoff). On total failure: use `defaultData()`, mark `canSave = false`, set attribute `DataLoaded = false`. Save on `PlayerRemoving`, every 60 s, and in `game:BindToClose`; skip when `canSave = false`. Merge loaded table over defaults so missing fields get defaults.
- [ ] **Step 2:** `Click` handler: drop if more than `Config.ClickLimitPerSec` in the current 1-second window, or no equipped tool held (character has a Tool named `data.equipped`). Else `applyClick` with `trainerMult` and `hasX2`, then `publish`.
- [ ] **Step 3:** `Buy`/`Equip`/`Rebirth`: validate with `canBuy`/ownership/`canRebirth`; ignore silently when invalid (`typeof(itemId) ~= "string"` included). After Buy/Rebirth call `Tools.give`.
- [ ] **Step 4:** `hasX2` / VIP ownership: `MarketplaceService:UserOwnsGamePassAsync` in `pcall`, cached per player at join; returns false when the pass id is 0.
- [ ] **Step 5:** Verify `rojo build -o build.rbxl` succeeds; `lune run tests/run` still PASS.
- [ ] **Step 6:** Commit `feat: server player data, remotes and rules`.
